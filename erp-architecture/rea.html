02 / connected architecture

Business → JDE → Decision

เลือกกล่องเพื่อขยายรายละเอียด ไม่ใช่ Flow เส้นเดียวแบบขบวนรถไฟ; แยก 3 Tier ตามหน้าที่

กำลังโหลด Workflow…

เลือก Node เพื่อเจาะลึก

ดูคำถามที่ต้องตอบ จุดตรวจสอบ และ Certification Gate ก่อนยืนยันว่าการทำงานถูกต้อง

แนวคิด REA: Business Event → P Object / Form / Version → Business View → Physical Data → Status / UBE → Downstream Decision → RCA. ความสัมพันธ์ระดับ Physical Table ยังไม่ผ่านการรับรอง

03 / developer + support workbench

Error ที่คนใช้เจอบ่อย ต้องย้อนรอยอย่างไร

เริ่มจากอาการ → เปรียบเทียบกรณีผิดพลาดกับกรณีสำเร็จ → ยืนยันกฎจริง ห้ามสั่ง Run ซ้ำเพื่อเดาสาเหตุ

RCA 6 ขั้นตอน

1 · อธิบายผลกระทบธุรกิจ ไม่เริ่มจากปุ่มที่กด
2 · ระบุ Key และ Grain เช่น SO Line / WO / Lot
3 · ระบุ Application / Version / User Role
4 · ตรวจข้อมูลต้นทาง → Status → Downstream
5 · เปรียบเทียบ Failed vs Success จากหลักฐานจริง
6 · รับรอง Root Cause → Fix → Prevent → QA

สถานะปัจจุบัน: 5 กลุ่ม RCA ยังไม่มีคู่เคสจริงที่ผ่านการรับรอง · Synthetic Tests 23/23 PASS ไม่ใช่การปิด RCA จริง

05 / closure program

แผนดำเนินการจาก REA ถึงระบบใช้งานจริง

ลำดับงานเป็น Stage Gate: เมื่อหลักฐานต้นทางไม่ผ่าน ห้ามปล่อยผ่านไปสู่ KPI/Automation

Architecture Guardrail: JDE ยังเป็น System of Record; การเชื่อมข้อมูลต้องเป็น Read-only ที่ได้รับอนุญาตผ่าน AIS/Orchestrator, Governed DB View หรือ Certified Export; หน้า Public ไม่เก็บข้อมูล ERP ระดับรายการ
06 / management + people enablement

แผนนำเสนอ 8 ตอน: เข้าใจง่าย แต่ไม่ตัดเนื้อหาสำคัญ

ใช้กับ Management Review, ERP Key User Workshop, Dev/Support Onboarding และการเตรียมงบ/สิทธิ์
