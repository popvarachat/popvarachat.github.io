API / Query Rules ที่ควรขอ IT พร้อม Field

  • ทุก dataset ต้องมี stable business key + updated_at เพื่อ incremental sync และป้องกัน duplicate
  • Date/time ขอเป็น ISO-8601 พร้อม timezone; หลีกเลี่ยง text date และเลขเวลาแยกคอลัมน์
  • Quantity ทุกช่องต้องมี UOM; ค่า null ต้องหมายถึง “unknown” ไม่ใช่ 0
  • อย่า aggregate Routing / PO / Inventory จนเสีย Line-level detail — Control Tower จะ aggregate เอง
  • ขอข้อมูลอย่างน้อยย้อนหลัง 12–24 เดือนเพื่อ calibrate lead time / capacity / variability
  • API รอบแรกเป็น read-only; write-back schedule เปิดหลัง UAT + Human Gate เท่านั้น

Architecture rules

  • No hidden business logic in UI/query
  • AI = recommendation, not production authority
  • Release / reprioritize / override ต้องมี Human Gate + audit
