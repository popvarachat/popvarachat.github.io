Status redesign

เดิมมี code เช่น 30 / 40 / 60 / 70 / 99 / 9D ปะปนกับ description. Target schema แยก status_code กับ cutting_status_event เพื่อเก็บ transition history, เวลา, source และผู้เปลี่ยนสถานะ ไม่ overwrite ประวัติ.

Key redesign

  • Inventory join ผ่าน item_id
  • TimeEntry → operation_event
  • Stock → time-stamped inventory_snapshot
  • Recommendation → planning_decision state PROPOSED / APPROVED / REJECTED

Implementation Baseline

โครงการถูกปักไว้เป็น design baseline เพื่อให้เริ่ม backend/database ต่อได้โดยไม่ต้องย้อนตีความ Access ใหม่

Build order

  1. PostgreSQL staging จาก schema.sql
  2. ETL 5 CSV ชุดปัจจุบัน → normalized tables
  3. Data-quality gates: orphan, duplicate, invalid date, status sequence
  4. Connector เพิ่ม PO / ControlPlan / Partlist
  5. Read-only API + Control Tower dashboard
  6. Rule engine: material readiness / late / WIP / bottleneck
  7. AI recommendations หลัง Human Gate

Architecture rules

  • Raw source immutable + row hash
  • No browser → DB direct write
  • No hidden business logic in UI/query
  • AI = recommendation, not production authority
  • Release / reprioritize / override ต้องมี Human Gate + audit
